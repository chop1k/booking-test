# Приложение для бронирования комнат в офисе

В общем смотри, я сейчас решаю тестовое задание, суть которого - разработать небольшое и простое приложение для бронирования комнат в офисе.

Я собираюсь реализовать его в виде телеграм WebApp. Помимо бекенда для этого мне потребуется сверстать несколько простеньких страниц.

Теперь давай я структурно опишу, какие есть странички и что у них должно быть.

## Страницы
Всего есть 2 страницы:
- основная страница;
- страница бронирования комнаты;

### Основная страница
Основная страница - это начальная страница, которая открывается при первом открытии приложения или при переходе по корневому пути (`/`).

Страница структурно состоит из следующих элементов:
- карточка "Забронировать комнату";
- карточка "быстрое бронирование";
- виджет календаря расписания бронирования комнат;

#### Карта бронирования комнат
Карта бронирования комнат помимо названия должна содержать картинку-коллаж с фотографиями 3х доступных комнат. Сам коллаж имеет следующую структуру:
- первая воловина картинки - полностью занята одной комнатой;
- вторая половина картинки - горизонтально поделена пополам на картинки двух разных комнат;

Карта бронирования должна быть кликабельна и при нажатии браузер должен перейти на страницу выбора комнаты для бронирования.

#### Карта быстрого бронирования
Карта быстрого бронирования комнат предназначена для более простого и быстрого бронирования комнаты, чем при обычном бронировании. Здесь не будет каких-то форм, требующих ввода данных, здесь не будет много уровней вложенности. Здесь будут только кнопки и одна выпадающая менюшка, за счёт чего можно двумя-тремя кликами забронировать комнату на предварительно заданное время.

Карта быстрого бронирования состоит из:
- заголовок (название карты и иконка выпадающего списка);
- список комнат, в котором каждый элемент состоит из:
  - название комнаты (занимает всё свободное горизонтальное место);
  - вместимость комнаты (количество сидящих мест, элемент имеет фиксированный размер);

При нажатии на заголовок список выпадает, или сворачивается. По дефолту он развёрнут.
При нажатии на элемент списка, открывается выпадающее меню выбора времени бронирования. Меню занимает примерно 60% экрана в высоту и может быть развёрнута во весь экран с помощью свайпа вверх, либо закрыта с помощью свайпа вниз или нажатия на пустую часть экрана.

Выпадающее меню выбора времени состоит из:
- блок выбора длительности бронирования;
  - кнопка "15 минут";
  - кнопка "30 минут";
  - кнопка "45 минут";
  - кнопка "60 минут";
- блок выбора начала бронирования;
  - кнопка "сейчас";
  - кнопка "через 15 минут";
  - кнопка "через 30 минут";
  - кнопка "через 45 минут";
  - кнопка "через 60 минут";
- кнопка "забронировать";

При нажатии на кнопку "забронировать", выполняется запрос на бронирование комнаты. При этом, в запросе указывается что никакое оборудование не используется.


Последовательность взаимодействия пользователя с картой следующая:
1. выбрать комнату;
2. выбрать длительность бронирования;
3. выбрать начало бронирования;
4. забронировать.

#### Календарь расписания бронирований
Календарь расписания бронирования комнат состоит из двух элементов:
- заголовок (название) "Расписание бронирований";
- функциональный блок, который состоит из следующих элементов:
	- горизонтальный переключатель месяца календаря, который состоит из:
		- кнопка переключения на предыдущий месяц;
		- название выбранного месяца;
		- кнопка переключения на следующий месяц;
	- таблица (7х7) дней календаря, которая состоит из следующих строк:
		- первая строка всегда фиксирована (одинакова независимо от месфца) и состоит из семи ячеек, каждая из которых некликабельна и содержит первые три буквы дня недели от понедельника до воскресенья соответственно; при этом выходные дни (суббота и воскресенье) тукслее чем будне дни;
		- остальные шесть строк содержат ячейки дней месяца (как текущего, так и прошлого и следующего); каждая ячейка кликабельна и открывает всплывающее меню просмотра расписания на выбранный месяц и день, каждая ячейка содержит число дня месяца; выходные дни и дни внешних месяцев имеют более тусклый цвет;

Всплывающее меню просмотра расписания на конкретный день конкретного месяца состоит из списка часов выбранного дня. Каждый элемент списка состоит из следующих частей:
- время (по часам, к примеру 13:00 - 14:00, 20:00-21:00);
- кружочки, представляющие собой аватарки забронировавших пользователей (если в часе больше чем одно бронирование); если количество бронирований больше чем 3, то количество аватарок ограничивается тремя и добавляется немного затемнённый кружок с троеточием по центру, обозначающий остальные аватарки;
Каждый элемент списка кликабелен. При нажатии на элемент списка, список раскрывается (расширяется) и снизу появляется похожий список бронирований в выбранный час, но теперь по минутам и с одной аватаркой (т.к. забронировавший всего один);
Всплывающее меню занимает примерно 60% экрана в высоту и может быть развёрнуто во весь экран с помощью свайпа вверх, либо закрыто с помощью свайпа вниз или нажатия на пустую часть экрана.

Последовательность взаимодействия пользователя со страницей следующая:
1. пользователь открывает приложение;
2. пользователь выбирает нужный раздел (страница выбора комнаты или страница просмотра конкретного дня из расписания);
3. пользователь что-то делает уже в конкретном разделе;
4. пользователь возвращается на основную страницу или закрывает приложение;

### Страница бронирования комнаты
Её основное назначение - показать список доступных для бронирования комнат и показать их основные характеристики и возможности чтобы пользователь выбрал подходящую комнату для бронирования.

Выйти из страницы можно тремя способами:
1. нажатие на кнопку "<" в левом верхнем углу;
2. свайпом слева направо;
3. нажатием кнопки "назад" на устройстве\браузере;

Страница по сути является списком из карточек, на каждую комнату по одной, которая состоит из:
- фотография комнаты;
- название комнаты;
- короткое описание комнаты;
- горизонтальный блок характеристик комнаты, который состоит из следующих элементов:
	- количество сидячих мест - имеет фиксированный размер;
	- блок оборудования комнаты - последовательность иконок, отражающих наличие или отсутствия оборудования конкретного типа в комнате; список возможного оборудования:
		- проектор\телевизор;
		- доска (мел\маркер\цифровая) для рисования;
		- кондиционер (климат контроль);
		- канцелярский набор (бумага\ручки\карандаши и т.д.);

При нажатии на карточку конкретной комнаты, открывается вплывающее снизу меню с формой бронирования комнаты. Форма занимает примерно 60% экрана в высоту и может быть развёрнута во весь экран с помощью свайпа вверх, либо закрыта с помощью свайпа вниз или нажатия на пустую часть экрана.

Форма бронирования комнаты состоит из следующих элементов:
- кнопка выбора даты и времени начала бронирования - при нажатии открывается виджет для выбора даты и времени;
- кнопка выбора даты и времени конца бронирования - при нажатии открывается виджет для выбора даты и времени;
- поле для ввода ожидаемого количества людей в комнате;
- список используемого оборудования - для каждого оборудования выбранной комнаты добавляется по одному переключателю; если переключатель включен - это значит что оборудование необходимо и используется, если нет - то нет;
- кнопка "Забронировать", при нажатии форма отправляется на сервер.

При нажатии на кнопку "Забронировать", текст кнопки заменяется на лоадер пока клиент ждёт ответа сервера. Когда ответ получен, текст меняется обратно.

При бронировании всего может быть 3 вида ответов от сервера:
- комната успешно забронирована;
- ошибка валидации формы;
- серверная ошибка;
При успешном ответе всплывающее меню закрывается. При неуспешном - над кнопкой появляется алерт с текстом ошибки. Если это ошибка валидации - поля с неправильными значениями меняют цвет на красный, остальные - на зелёный.

Последовательность взаимодействия пользователя со страницей следующая:
1. пользователь выбирает комнату;
2. пользователь вводит форму;
3. пользователь жмёт кнопку "Забронировать";
4. пользователь закрывает форму, либо исправляет ввод и повторяет последовательность.

## Технологии
Само приложение реализуется на PHP 8.6 с Symfony 8.1 и Twig 3.28 с stimulus-bundle. Работа с телеграмом осуществляется напрямую запросами к апи, без посредников в виде библиотек.
